# Заметка об использовании искусственного интеллекта (AI_NOTE)

Согласно разделу 5 регламента индивидуального проекта «Объясни задачу», использование инструментов искусственного интеллекта разрешено при условии открытого описания целей использования, принятых/отклонённых рекомендаций и методов проверки результатов.

Автор проекта несёт полную ответственность за исходный код и понимает его внутреннее устройство.

---

## 1. Для чего использовался ИИ
ИИ-ассистент применялся на этапах проектирования, разработки и тестирования в следующих задачах:
1. **Проектирование архитектуры**: помощь в выборе шаблона проектирования (SoC + Reactive State Container) для изоляции математического движка блок-схем от компонентов пользовательского интерфейса.
2. **Геометрические расчёты для SVG**: вычисление координат узлов и точек перегиба ортогональных связей (`Waypoints`) для соблюдения пропорций фигур по ГОСТ 19.701-90.
3. **Генерация каркаса модульных тестов**: подготовка шаблонных тест-кейсов xUnit для верификации граничных условий.
4. **Поиск и диагностика ошибок компиляции**: диагностика конфликта синтаксиса Razor при использовании SVG-элементов `<text>` внутри директив `@if`.

---

## 2. Какие советы ИИ были приняты
- **Выбор Blazor WebAssembly**: рекомендация скомпилировать строго типизированную логику C# в WebAssembly для бесплатной статической публикации на GitHub Pages (что напрямую закрывает критерий оценки 7 без затрат на серверный хостинг).
- **Паттерн Неизменяемого Снимка (Immutable Snapshot)**: реализация класса `FlowchartStepSnapshot`, фиксирующего состояние переменных и пройденных ребер на каждом шаге. Это обеспечило детерминированную работу кнопки «Назад» без повторных пересчётов.
- **Модель типизированного значения (`VariableValue`)**: рекомендация оформить значение переменной в виде `readonly struct` с перегрузкой операторов и контролем типов (`int`, `decimal`, `bool`, `string`), исключая скрытые ошибки приведения типов.

---

## 3. Какие советы ИИ были исправлены или отклонены
- ❌ **Отклонено (Использование внешних JS-библиотек визуализации)**:
  - *Предложение ИИ*: подключить сторонние библиотеки графов на JavaScript (Mermaid.js или Cytoscape.js).
  - *Причина отклонения*: нарушает требование об использовании строго типизированного языка (C#) для ключевых частей приложения. Сторонние библиотеки усложняют настройку ГОСТ-фигур (ромбы ветвления, параллелограммы ввода-вывода) и не позволяют динамически привязывать C#-делегаты и анимацию пройденных путей.
  - *Решение*: написан собственный SVG-рендерер `FlowchartViewer.razor` на Blazor.
- ⚠️ **Исправлено (Синтаксис SVG `<text>` в Razor)**:
  - *Ошибка ИИ*: сгенерировал разметку с тегом `<text x="0" y="16">` внутри блоков `@if`. Это вызвало ошибку компилятора Razor `RZ1023` («<text> and </text> tags cannot contain attributes»), так как парсер счёл тег внутренней директивой Razor для вывода неразмеченного текста.
  - *Исправление*: разработан вспомогательный `RenderFragment` метод `RenderSvgText(...)`, формирующий элементы SVG-текста через программный `RenderTreeBuilder`.
- ⚠️ **Скорректировано (Формулы задачи Типа 2)**:
  - *Первоначальный вариант ИИ*: задача самостоятельного подбора допускала неограниченный диапазон цен, из-за чего ученик мог ввести тривиальные гигантские числа.
  - *Исправление*: введены строгие педагогические рамки (цена 50..250 руб., количество 5..20 шт.) с эвристическими подсказками при отклонении от целевой ветви.

## 4. Как проверялся результат работы ИИ
1. **Автоматическая верификация**: прогон набора модульных тестов `dotnet test` (5 обязательных сценариев, 100% успешное прохождение).
2. **Сборка релизного пакета**: выполнение `dotnet publish -c Release` с проверкой на отсутствие предупреждений компилятора (`Warnings: 0, Errors: 0`).
3. **Ручное тестирование**: сквозная пошаговая проверка каждого из трёх алгоритмов в браузере, проверка адаптивности макета при уменьшении окна до мобильных размеров (375px) и валидация сценариев самостоятельной задачи.
